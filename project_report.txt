# ANALYSIS OF RSA COMPUTATIONAL COMPLEXITY FOR DIFFERENT KEY SIZES

## 1. Introduction

RSA (Rivest–Shamir–Adleman) is a widely used public-key cryptographic algorithm that provides secure communication and data protection. It uses a pair of keys: a public key for encryption and a private key for decryption.

The security of RSA depends largely on the difficulty of factoring large integers. As the RSA key size increases, security generally improves, but the computational resources required for cryptographic operations may also increase.

This project analyzes RSA computational performance for key sizes of 1024, 2048, 3072, and 4096 bits by measuring key generation, encryption, and decryption execution times using Python.

## 2. Problem Statement

RSA performance varies with key size, affecting the time required for cryptographic operations. The objective is to experimentally evaluate these differences and understand the trade-off between computational performance and security.

## 3. Objectives

* Implement RSA cryptographic operations using Python.
* Evaluate RSA key generation, encryption, and decryption times.
* Compare the performance of different RSA key sizes.
* Represent the experimental results using graphs.
* Understand the relationship between key size, computational cost, and security.

## 4. Tools and Technologies

* Programming language: Python
* Cryptographic library: Cryptography
* Data processing: Pandas
* Visualization: Matplotlib
* Development environment: Visual Studio Code or PowerShell
* Cryptographic padding: RSA-OAEP with SHA-256

## 5. Methodology

1. Configure the Python environment and install the required libraries.
2. Select RSA key sizes of 1024, 2048, 3072, and 4096 bits.
3. Generate RSA public and private key pairs.
4. Measure the time required for key generation.
5. Encrypt a sample plaintext using the public key and OAEP padding.
6. Decrypt the ciphertext using the private key.
7. Verify that the decrypted message matches the original plaintext.
8. Repeat the experiments five times and calculate average execution times.
9. Save the results in CSV format and generate comparison graphs.

## 6. Results and Discussion

The experiments measured the average execution time for key generation, encryption, and decryption.

| Key size  | Key generation (ms) | Encryption (ms) | Decryption (ms) |
| --------- | ------------------: | --------------: | --------------: |
| 1024 bits |             17.1761 |          2.4835 |          0.5537 |
| 2048 bits |             61.4958 |          0.1144 |          1.3062 |
| 3072 bits |            285.4586 |          0.1306 |          2.7961 |
| 4096 bits |            311.4099 |          0.1886 |          5.4170 |

Key generation time increased overall with key size. Decryption time also increased across the tested key sizes. Encryption timings were small for the 2048-, 3072-, and 4096-bit keys, while the 1024-bit measurement was unexpectedly high. This may reflect measurement variability or system conditions and should be investigated with additional runs.

The graphs generated by the Python program provide a visual comparison of the measured execution times.

## 7. Conclusion

This project experimentally analyzed the computational performance of RSA for four different key sizes. The results showed that larger keys generally required more time for key generation and decryption in the tested environment.

The experiment highlights the trade-off between security and computational cost in public-key cryptography. For real-world applications, 2048-bit RSA or stronger is generally preferred; 1024-bit RSA is included here for academic comparison only.

The measurements are specific to the system and software environment used. Repeating the experiments under controlled conditions can provide more reliable performance estimates.
